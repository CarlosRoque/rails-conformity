rails-conformity — architecture

One registry drives everything: the gate blocks new violations, the ratchet absorbs old debt, and the codifier turns approved patterns back into conventions.

The diagram

1. How it works, in order

Measure (install + report)

  • conformity:install writes the policy, an empty registry, and the baseline: every current violation becomes a rule:file key. The app starts green, in debt.
  • conformity:report scans changed files through four providers: convention rules (regex), rubocop, the test suite, and provenance vs generator output. Each finding gets a score and a recommended fix command.

Gate (every push, every edit)

  • conformity:check re-runs the providers and compares against the baseline. exit 0 nothing new. exit 2 new findings on stderr — CI or the pre-push hook stops the push.
  • bin/conformity edit-check is the fast path for agent hooks: no Rails boot, reads the baseline as plain YAML, flags only findings the baseline doesn't cover. Legacy debt files pass silently.
  • changed-check escalates to the full gate (runs the suite).

Decide (triage)

  • conformity:triage walks every finding. Each one gets exactly one of four decisions, stored in the registry: codify it's a convention, exempt allowed but dated, reject not acceptable + TODO note, keep undecided.

Codify (close the loop)

  • The family scanner groups structurally identical files in app/services, models, jobs, controllers by a loose digest, then only surfaces groups that pass the round-trip test: the extracted template must rebuild every original byte-for-byte.
  • codify_generator writes a real Rails generator (bin/rails g team:pattern Name) plus the test-role template (rspec or minitest, whichever the family has) and registers it.
  • codify_cop writes a RuboCop cop and admits it only after a corpus test: fires on every bad example, silent on every good one.
  • Both register paths into the registry — steering re-renders, provenance starts watching, and the family stops nagging as a candidate.

2. What lands in a host app

PathRole
conformity/registry.ymlSource of truth: generators, cops, exemptions, rejects. Hand-edits are legit; steering derives from it.
conformity/baseline.ymlThe ratchet. Deduped rule:file keys of known debt + score. Only shrinks through fixes.
config/conformity.ymlPolicy: score weights, thresholds, provider strictness (strict/advisory), decision routing.
AGENTS.md + docs/conventions/*Rendered steering. Never hand-edit; gate flags drift.
.claude/skills/conformity/SKILL.mdThe agent playbook: hard rules, gate loop, codify/reject walkthrough.
bin/conformityNo-boot shim: edit-check, changed-check. Read by all host hooks.
.claude/settings.json · .codex/hooks.json · opencode.json · .git/hooks/pre-pushHost wirings. Same evaluator, four consumers.
lib/generators/team/* · lib/rubocop/cop/convention/*Codify outputs: the generator + templates; the corpus-tested cop.
